# DLSSG Native 0.2.4

[简体中文](README.md) | [English](README.en.md) | Русский

Windows x64 / D3D12. После закрытия игры поместите `version.dll` и `dlssg_sm86.ini` рядом с настоящим исполняемым файлом рендеринга игры, предварительно сохранив прежние файлы.

DLL содержит нативную оболочку C++, PTX/Cubin для SM75/SM86, модель и граф инференса. Она не извлекает, не загружает и не отображает в память исходную DLL генерации кадров. По-прежнему необходимы интерфейсы NVIDIA NGX/NVAPI/CUDA из установленного драйвера; CUDA Toolkit не нужен.

## Что нового в 0.2.4

- **Видеопамять:** устранено удержание старых текстур после пересоздания входных ресурсов; представления переиспользуются только после фактического уничтожения ресурса.
- **История кадров:** исправлено обновление истории без HUD и истории искажения при пропусках входов и Reset; это устраняет некорректные сгенерированные кадры, воспроизводившиеся офлайн.
- **Корректность результата:** установлен флаг пропуска недопустимых сгенерированных кадров, чтобы вызывающая сторона не использовала устаревшее значение.
- **Настройки по умолчанию не менялись:** сохранены точные оптимизации, необязательная приближённая выборка, пять ключей INI и пять подписанных точек входа прокси. Добавлены регрессии для динамических входов, маршрута SM75 и памяти; о мерцании, о котором сообщали пользователи, всё ещё требуется проверка в игре.

## Требования

- **Система и игра:** Windows 10/11 x64, D3D12 и игра, способная включить DLSS Frame Generation через этот мод. Процессор и системная память должны соответствовать требованиям самой игры.
- **Видеокарта и маршрут:** SM86 предназначен для RTX 30-й серии, SM75 — для RTX 20-й серии. Физическая проверка выполнена на RTX 3080 Ti. SM75 проверен на этой карте через forward PTX; физическая проверка Turing/Cubin пока не выполнена.
- **Драйвер и зависимости:** нужны интерфейсы NGX/NVAPI/CUDA драйвера NVIDIA. Измерения проводились на драйвере 591.86; это проверенная версия, не объявленный минимум. Для игры не нужны CUDA Toolkit и Python.
- **Видеопамять:** оставляйте запас для самой игры, ресурсов FG и изменений сцены. Windows и фоновые приложения тоже используют VRAM.

### Дополнительная VRAM по конфигурации

Ниже приведены ориентировочные значения для 0.2.4, RTX 3080 Ti, драйвера 591.86 и PTX. Все 27 случаев включают точный SM86, приближённый SM86 и маршрут SM75. Выбирайте по итоговому **выходному разрешению**: DLSS Performance при 4K всё равно использует строку 4K.

| Выходное разрешение | 2X: примерная дополнительная VRAM | 3X | 4X |
|---|---:|---:|---:|
| 1080p / 1920×1080 | около 320 MiB | около 330 MiB | около 340 MiB |
| 2K / 2560×1440 | около 490 MiB | около 510 MiB | около 520 MiB |
| 4K | около 700 MiB | около 740 MiB | около 770 MiB |

Значения получены как прогретое увеличение VRAM процесса: из него вычтены заранее загруженные входы теста и тестовый выход, затем добавлена группа из `M` 32-битных выходных буферов. Они округлены вверх до 10 MiB (1 GiB = 1024 MiB). Это устойчивые ориентиры, а не пиковые значения или минимальные требования к карте. Ресурсы игры, дополнительные кадры в очереди, swap chain и крупные форматы пикселей требуют дополнительного запаса. Цифры SM75 — ориентир по измерениям на 3080 Ti.

В точном и приближённом режимах использовался одинаковый объём VRAM. Для SM75 разница меньше 1 MiB. 2X/3X/4X используют общие постоянно загруженные ресурсы, поэтому уменьшение множителя в основном сокращает выходные буферы и может почти не уменьшить суммарное потребление памяти.

**Нехватка VRAM или превышение выделенного Windows бюджета памяти может вызвать редкие рывки и пики времени кадра даже при нормальном среднем FPS.** Уменьшите качество текстур, выходное разрешение или трассировку лучей и освободите VRAM от фоновых приложений. [Руководство Microsoft по бюджету видеопамяти](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo)

## Установка и обновление

Нужны Windows x64, игра D3D12 и драйвер NVIDIA. Python и CUDA Toolkit для игры не требуются. Текущая модель — 310.1; поддержка Vulkan запланирована позже.

1. Закройте игру. При обновлении сохраните прежние прокси-DLL и INI этого проекта в отдельную папку и удалите старый прокси из папки игры. Не трогайте файлы других модов.
2. Найдите настоящий EXE рендеринга. Например, у Black Myth: Wukong это `D:\SteamLibrary\steamapps\common\BlackMythWukong\b1\Binaries\Win64`, где расположен `b1-Win64-Shipping.exe`.
3. Скопируйте рядом с ним **одну прокси-DLL и `dlssg_sm86.ini`**. По умолчанию это корневой `version.dll`. Альтернативы: `altnative/winmm.dll`, `dinput8.dll`, `winhttp.dll` и `dxgi.dll`. Выберите имя библиотеки, которую загружает игра, сохраните его имя и держите установленной только одну прокси-DLL этого комплекта.
4. Для RTX 3080 Ti используйте `Router=SM86, KernelImage=PTX`; для Turing/SM75 — `Router=SM75, KernelImage=PTX`. INI общий для всех точек входа.
5. Перезапустите игру, включите DLSS Frame Generation и выберите множитель в игре. `MaxGeneratedFrames=3` разрешает до трёх дополнительных кадров, то есть итоговые 4X; фактическое количество выбирает игра.

Каждая прокси содержит полный нативный runtime. Сохраняйте конфликтующие DLL других модов и выберите другую свободную точку входа. Не смешивайте этот пакет с прокси, инжекторами или backend-файлами upstream-проекта SM75.

Точный режим по умолчанию — `HardwareBilinear=0`. Необязательный приближённый режим `1` действует только на SM86 и может менять пиксели генерации. После изменения INI перезапустите игру. См. [описание конфигурации](docs/NATIVE_INI.md).

Для диагностики загрузки временно задайте `Logging.Level=2` и проверьте `dlssg_sm86/logs` рядом с EXE. Если журнала проекта нет, проверьте папку настоящего EXE и то, загружает ли игра выбранную DLL. Для обычной игры верните `Level=1`. Сохраняйте оригинальные DLSSG-файлы игры. Для удаления закройте игру, удалите DLL и INI этого пакета, а для отката восстановите резервную копию.

## Ложные срабатывания антивируса и подпись

Мод использует системную DLL-прокси и хуки LoadLibrary для интеграции с игрой. Такое поведение может вызывать эвристические ложные срабатывания. Нативная интеграция исключает извлечение и ручное отображение исходной DLL функции, однако хуки интеграции остаются необходимыми. Только производитель средства защиты может определить, является ли конкретное обнаружение ложным.

Все пять DLL подписаны самоподписанным сертификатом **DLSSG Native Project**, видимым на вкладке «Цифровые подписи» свойств файла. Подпись подтверждает личность подписанта и целостность файла, но **не устанавливает доверие Windows по умолчанию и не гарантирует отсутствия предупреждений антивируса**. Недоверенная цепочка сертификатов, репутационное предупреждение SmartScreen и обнаружение вредоносного ПО — отдельные проверки. [Справка Microsoft SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

При обнаружении сначала сверьте источник скачивания и ZIP релиза с его файлом `.sha256`. Зафиксируйте продукт защиты, имя обнаружения, версию баз и SHA256 DLL, затем запросите проверку ложного срабатывания у производителя. Для Microsoft Defender используйте [Microsoft file analysis](https://www.microsoft.com/en-us/wdsi/filesubmission). Совпадение хешей и подписи не заменяет проверку производителя.

## Единая база сравнения: Release 0.1.0 → Native 0.2.4

Каждая строка использует в качестве базы `dist/Release/version.dll` от 07.09.2026, SHA256 `03d445237d519ac48cd9226278a0f07aecd7ac597697697eb64404e1d51b3c5a`. Оба режима используют подписанную DLL 0.2.4 `c844646d…`, включённую в этот релиз. Все девять условий заново измерены на RTX 3080 Ti / SM86, драйвер 591.86.

Время — это **миллисекунды GPU для всей группы генерации на один реальный кадр**, включая общую предобработку. 2X/3X/4X создают 1/2/3 дополнительных кадра. Точный режим — `HardwareBilinear=0`; приближённый — `1`.

| Разрешение | Множитель | Release 0.1.0, мс | 0.2.4 точный, мс | Улучшение | 0.2.4 приближённый, мс | Улучшение |
|---|---:|---:|---:|---:|---:|---:|
| 1080p | 2X | 1.530 | 0.990 | 35.26% | 0.981 | 35.90% |
| 1080p | 3X | 2.252 | 1.594 | 29.23% | 1.572 | 30.21% |
| 1080p | 4X | 2.979 | 2.201 | 26.13% | 2.160 | 27.49% |
| 2K / 1440p | 2X | 2.497 | 1.638 | 34.38% | 1.629 | 34.77% |
| 2K / 1440p | 3X | 3.774 | 2.610 | 30.84% | 2.575 | 30.21% |
| 2K / 1440p | 4X | 4.958 | 3.579 | 27.82% | 3.706 | 25.26% |
| 4K | 2X | 3.186 | 2.099 | 34.12% | 2.066 | 35.14% |
| 4K | 3X | 5.071 | 3.453 | 31.90% | 3.366 | 33.61% |
| 4K | 4X | 7.115 | 4.804 | 32.48% | 4.752 | 33.21% |

Улучшение вычисляется как `(время Release − текущее время) / время Release` до округления. Значения — медианы медиан. В каждом условии выполнено четыре раунда, Release запускался до и после каждого, а точный и приближённый режимы чередовались. Всего 144 запуска по 256 групп; частоты GPU не фиксировались, выбросы не удалялись.

Все режимы используют одинаковые синтетические входы формата Wukong, PTX, вычислительную очередь HIGH=100 и независимую отправку каждого Evaluate. После 1,5 секунды прогрева выполняются Reset и 64 прогревочных кадра. Для старого Release Auto/Cubin явно заменён на PTX. Его исходная DLL функции 310.1 загружается с совпадающим хешем; затраты на инициализацию, извлечение и загрузку не включены в измерения.

Точные результаты после замеров совпадают с Release байт в байт. Приближённый режим сохраняет реальные кадры и альфа-канал, но меняет RGB сгенерированных кадров. Интервал GPU-группы включает разрывы отправки между Evaluate. Рендеринг, Present, загрузки и чтения не входят в результат, поэтому эти улучшения не являются измерением прироста игрового FPS.

Результаты 1440p 4X сильно различались, и медиана приближённого режима оказалась медленнее точного; таблица сохраняет эти данные. В 20 дополнительных чередующихся запусках против 0.2.3 медиана каждого режима отличалась менее чем на 0,4%, без чёткого регресса. Приближённый режим не гарантированно быстрее — сначала используйте точный.

## Оценка FPS с генерацией кадров

Сначала отключите генерацию кадров в **той же сцене, с тем же выходным разрешением, режимом DLSS Super Resolution и графическими настройками** и измерьте `F_off`. Базовое время кадра: `1000 / F_off`. Затем выберите время всей группы генерации `T_FG` для своего разрешения, множителя и режима.

```text
Базовое время кадра T_base (мс) = 1000 / F_off
Время группы с FG T_group (мс) ≈ T_base + T_FG
Скорость реальных кадров / групп G (групп/с) ≈ 1000 / T_group
Итоговый FPS с FG F_out ≈ G × M
                     = 1000 × M / (1000 / F_off + T_FG)
```

`M` — итоговый множитель: 2, 3 или 4 для 2X, 3X или 4X. Группа включает один реальный и `M − 1` сгенерированных кадров. **`T_FG` из таблицы уже включает все сгенерированные кадры и общую предобработку; не умножайте его повторно на `M − 1`.** Скорость реальных кадров с FG в этой оценке ниже, чем `F_off`.

Например, **50 FPS без FG** означает базовое время **20 мс**. Для RTX 3080 Ti / SM86, 4K и 4X:

| Конфигурация | Время группы FG, мс | Оценочное время группы, мс | Реальных кадров / групп в секунду | Итоговый FPS |
|---|---:|---:|---:|---:|
| Release 0.1.0 | 6.748 | 26.748 | 37.4 | 149.5 |
| 0.2.4 точный по умолчанию | 4.804 | 24.804 | 40.3 | 161.3 FPS |
| 0.2.4 приближённый | 4.752 | 24.752 | 40.4 | 161.6 FPS |

Для 1080p, 1440p, 2X и 3X используйте подходящую строку и собственный замер `F_off`. Эти показатели получены на 3080 Ti; для других карт и SM75 нужны отдельные измерения. Это грубая аддитивная оценка. Конкуренция за ресурсы GPU, синхронизация, нагрузка CPU, лимиты FPS и частота монитора влияют на результат; расчёт может не совпадать со счётчиком FPS или числом реально показанных кадров.

## Отзыв о Black Myth: Wukong

Пользовательские приблизительные замеры одной сцены: RTX 3080 Ti, 4K, DLSS Performance, Full Ray Tracing выключен, графика Cinematic. Без FG — около 50 FPS; с 4X FG:

| Состояние | Реальных кадров / групп в секунду | Общий FPS со сгенерированными кадрами |
|---|---:|---:|
| До оптимизации | около 36 | около 144 |
| После оптимизации 0.2.3 | около 40 | около 160 |

Обе скорости выросли примерно на 11,1%: +4 группы/с и +16 FPS. Это наблюдения пользователя, а не расчёт; для 0.2.4 они заново в игре не проверялись. Офлайн-ускорение GPU не переводится напрямую в такой же процент прироста игрового FPS.

## Конфигурация

Поставляемый INI содержит пять ключей: `Router=SM86`, `KernelImage=PTX`, `HardwareBilinear=0`, `MaxGeneratedFrames=3` и `Logging.Level=1` (только ошибки). Игра выбирает фактический множитель до 4X. После изменений перезапустите игру.

Для Turing или forward-PTX-тестов SM75 используйте `Router=SM75`. На 3080 Ti для SM75 нужен PTX или Auto. Cubin требует точного совпадения физической архитектуры и Router. SM75 использует собственный путь ядер и исходную очистку D3D12; слияния SM86, CUDA-очистка и приближённая выборка к нему не применяются. Физическая проверка Turing/Cubin ещё не завершена.

Точные и приближённые пресеты находятся в `config/presets`. Устаревшие ключи оптимизации в старых INI игнорируются. См. [детали INI](docs/NATIVE_INI.md).

## Границы проекта

Сохранены типобезопасное исправление UI из 0.2.2 и инициализация на первом Evaluate. Нужны явные прямые/обратные матрицы отсечения. Релиз поддерживает до трёх дополнительных кадров; 6X/динамические множители, Reflex Warp и автоматический поиск матрицы Reflex не реализованы. Вызывающая сторона отвечает за отправку в очередь, синхронизацию и вывод. Офлайн-выигрыш GPU не является измерением игрового FPS.

Для диагностики задайте `Logging.Level=2` или `3`; журналы пишутся в `dlssg_sm86/logs`. Forward PTX SM75 проверен на 3080 Ti; физическая Turing/Cubin и длительная проверка в играх остаются незавершёнными. Сохраняйте оригинальные DLSSG-файлы игры. Чтобы удалить пакет, удалите его DLL и INI.
